# QCL Native Pack 001

Audited C# / Lean-compatible native engine upgrade package for quantitative research workflows.

## How the mutations were discovered

The mutations evaluated here were **not created by training on market data, optimizing historical returns, or searching financial price series for profitable parameters or patterns**.

They were generated by a separate engine built to explore **cross-domain mathematics**: mathematical structures and relationships drawn from scientific and technical domains outside conventional quantitative-finance optimization.

The discovery engine is **entirely deterministic**. It does not use AI, machine-learning models, or language models to determine the QCL mutations. The mutations are generated by proprietary deterministic algorithms developed for cross-domain mathematical discovery.

Market data entered only at the subsequent validation stage, when the already-generated mutations were executed and measured in QCL / QuantConnect Lean.

This distinction is central to the result. The reported performance is therefore not the outcome of fitting the mutation-generation process to the same market history on which the mutations were later evaluated.

Conceptually, the workflow was:

`cross-domain mathematics -> mutation generation -> QCL / Lean implementation -> market-data validation`

The empirical question tested here is whether mathematical structure discovered outside market-price optimization can produce useful executable changes when transferred into a quantitative trading engine.
